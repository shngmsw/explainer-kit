1「図解して」と頼むと何が起きるのか

「この仕組みを、詳しくない人にもわかるように図解して」。この一言から Word や PDF の資料が出来上がるまでを、一続きで追いかけます。

まず、この道具が置かれている場所から説明します。舞台は Claude Code です。

Claude Code：文章で書いた指示を受け取り、調べ物やファイルの作成といった作業を代行するツール。もともと開発者向けに作られたもので、手元のパソコンやブラウザ上で動きます。

Claude Code には、特定の作業のやり方をあらかじめ書き留めておく仕組みがあります。これをスキルと呼びます。

スキル：「こういう依頼を受けたら、この手順で進める」と書いてある手順書。該当する依頼が来たときにだけ読み込まれます。 プラグイン：関連するスキルをまとめた詰め合わせ。1回の導入操作で、中のスキルがすべて使えるようになります。

explainer-kit は、2つのスキルを収めたプラグインです。依頼を受け取るのはzukai-onepager（図解して書く係）で、これが1枚HTMLを作ります。そのあとhtml-to-deliverable（納品用に清書する係）が、Word・PDF・Google ドキュメントに変換します。

途中にlint ゲート（図の検査）がありますが、これは独立した工程ではなく zukai-onepager の中の一段です。図が仕上がった時点で機械が寸法を検査し、合格しなければ先へ進みません。

覚えるのは1本の流れだけ

依頼 → zukai-onepager → 1枚HTML → html-to-deliverable → 納品物。以降の章は、この流れのどこを説明しているのかを確かめながら読んでください。

2誰に向けて書くのか

この道具が想定する読者は「詳しくないが、仕事はできる大人」です。誰に向けて書くかが決まると、書き方の原則も決まります。

想定読者は、その領域の専門家ではないが、読解力と業務経験はある人です。他部署の担当者、クライアントの窓口、着任したばかりの管理職あたり。前提知識は無いが、説明されれば理解できる相手だと考えます。

この読者像から、zukai-onepagerの3つの原則が導かれます。

1. 難しさは説明で解く

専門語やカタカナ語は、使ったその場で1行開き、巻末の用語集にも載せます。言葉づかいを子供向けにするのではなく、内容の側を噛み砕きます。フリガナや絵文字は使いません。

2. 図解は各章に置く

冒頭に1枚だけ図を置いて、あとを文字の壁にしません。図はその章の主張そのものを描きます。1つの章で言うことは1つに絞ります。

3. 器は1枚、語りは毎回設計する

出来上がりの形（自己完結した1枚HTML）は固定しますが、章立てと語り口は題材ごとに考え直します。

この資料が「1件の依頼を追いかける」という語り口をとっているのも、3番目の原則の結果です。決まった型に流し込んだのではなく、この題材にはこの順序が一番腑に落ちると判断して選んでいます。

噛み砕くのは内容であって、言葉づかいではない

無説明の専門語で読者を置き去りにするのも、幼児向けの語り口にするのも、どちらも失敗です。社外にそのまま出せる文体を保ちます。

31枚HTMLができるまで

依頼を受けてから 1枚HTML が出来上がるまでは、7つの段階を順に進みます。いきなり書き始めることはしません。

依頼を受けたzukai-onepagerの進め方は次の通りです。

  1. 対象を理解する（コードや資料を読む。わからないまま書かない）
  2. 登場する要素の呼び名と色を決める
  3. 語り（見せる順番）と、各章の言いたいこと1つを設計する
  4. 図を1枚ずつ描く
  5. HTML に組み上げる
  6. lint ゲートを通す
  7. 検品チェックリストで最終確認する

4番目の作図は、図ごとに別の担当を立てて並行して進めます。

サブエージェント：本体とは別に立てられる作業担当。指示を渡すと、その1件だけを引き受けて結果を返します。図のように互いに独立した成果物は、枚数分をまとめて同時に進められます。

5番目で出来上がるのが1枚HTMLです。

1枚HTML：本文・表・図をすべて1つのファイルに収めた資料。ブラウザで開くだけで読め、他のファイルを必要としません。 インラインSVG：図を画像ファイルとして外に置かず、線と文字の指定として HTML の中に直接書き込んだもの。拡大しても粗くならず、寸法を後から機械で検査できます。

「登場要素ごとに1色」の実例

2番目の段階でやっている色決めは、この資料自身が実例になっています。依頼は青、zukai-onepagerは橙、1枚HTMLは緑、html-to-deliverableは紫、lint ゲートは桃。本文の文字色と図の中の色は同じ値を使い、章が変わっても対応を変えません。読者が色を手がかりに追えるようにするためです。

4図が崩れていないかを機械で確かめる

図が組み上がると、機械が寸法を検査します。エラーもワーニングも0でなければ、その資料は先へ進めません。

lint ゲートはzukai-onepagerの6番目の段階で、組み上がった1枚HTMLの中の図をまとめて検査します。

lint：書かれたものを機械的に読み、決まりごとに反していないか指摘する検査。指摘は明確な違反である「エラー」と、推奨から外れている「ワーニング」に分かれます。

検査の中身そのものは、外部のスキルが持っています。

svg-diagram：図の描き方の決まりごと（箱の高さ、文字の縦位置、矢印の余白など）と、それを検査するツール svg-lint を提供する外部スキル。zukai-onepager はこれを前提にしており、入っていないと lint ゲートは動かずに止まります。

指摘には「実際の値 → あるべき値」が付きます。そのまま直して再実行し、指摘が消えるまで繰り返します。ワーニングを「推奨にすぎないから」と残すことはしません。

なぜ人の目ではなく機械なのか

理由は枚数と細かさです。1つの資料に図は6枚前後入り、1枚の図には数十個の箱と矢印があります。矢印の先端が箱から5ピクセル離れているか、文字の縦位置が箱の中心から規定どおりずれているか——これを全部人が見るのは現実的ではありません。機械は何度でも同じ精度で見ます。

合格の線は1本

エラー0・ワーニング0。ここを通らない図は、そのあとの納品物にも入りません。

5Word・PDF・Google ドキュメントに変える

1枚HTML をもとに、配布用の3つの形を作ります。図を描き直すことはありません。

html-to-deliverableは、出来上がった1枚HTMLを受け取り、納品用に清書する係です。経路は3つあります。

Word（docx）

図を Chrome で表示させて画像に変換し、本文とともに docx ファイルへ組み直します。章ごとに改ページされ、見出しや表もそのまま移ります。

PDF

印刷用CSSを当ててから、Chrome の印刷機能で出力します。この資料では用紙A4、余白は上下16mm・左右15mm を指定しています。

Google ドキュメント

いったん docx を作り、それを Google ドライブへ変換アップロードします。追加の認証設定が必要な経路です。

Chrome：ウェブブラウザ。ここでは人が閲覧するためではなく、画面を出さずに HTML を読み込ませ、図の画像化と PDF 出力をさせる道具として使います。 印刷用CSS：画面で読むときの体裁とは別に、紙に出すときの版面（用紙サイズ、余白、どこで改ページするか）を指定した記述。当てずに出すと画面用の版面のまま印刷され、ページ数が無駄に増えます。

どの形式が要るかは、必ず先に確認します。3つ全部を黙って作ることはしません。使わないファイルが保存先に増えるためです。

向かない場面もあります。対面で映すスライドが欲しいときは、本文が落ちてしまうのでこの経路は使いません。Markdown（見出しや箇条書きを記号だけで書く簡易な記法）が正本になっている文書も、そちらから直接変換したほうが早く済みます。

6直すときは HTML だけ直す

手を入れる先は 1枚HTML の1箇所だけです。Word や PDF を直接編集することはありません。

1枚HTMLが正本で、Word・PDF・Google ドキュメントは派生物です。

正本と派生物：正本は、内容を直すときに手を入れる唯一のファイル。派生物は、正本から機械的に何度でも作り直せる複製です。

誤字を見つけたときも、図の矢印を1本描き替えたいときも、直すのは HTML です。直したらhtml-to-deliverableをもう一度実行すれば、指定した形式の納品物がすべて作り直され、3つの間で内容がずれることがありません。

逆に、やらないことが2つあります。1つは作図のやり直しです。図は HTML の中にあり、変換のたびに画像化されるので、描き直す必要がありません。もう1つは Word を開いての直接編集です。その修正は HTML に残らないため、次の再実行で消えます。

一箇所を直せば全部に届く

この一方通行を守っている限り、「どれが最新版か」を人が管理する必要はなくなります。

8使い始めるには

導入は2手です。Claude Code の入力欄に、次の行をそのまま打ち込みます。

/plugin marketplace add shngmsw/explainer-kit
/plugin install explainer-kit@explainer-kit

あわせて、図の検査に使う外部スキル svg-diagram を入れます。こちらは端末（コマンドを打ち込む画面）で実行します。

npx skills add bybit-exchange/svg-diagram -g

あとは Claude Code に「この仕組みを、詳しくない人にもわかるように図解して」と頼むだけです。配布用の形が要るときは、「この資料を Word にして」と続けます。
